Next.js 핵심 개념 4가지
1. 라우팅과 랜더링
2. 데이터 패치
3. 캐싱
4. 최적화

라우팅: URL에 따라 어떤 페이지를 그려줄 것인가
렌더링: 라우팅에 따라 페이지를 그리는 것

Next.js는 폴더 '규칙'에 맞게 프로젝트를 구성하면 자동으로 라우팅함(폴더 경로가 곧 URL 경로)

layout: 모든 하위 페이지에 모두 적용되는 양식
-> 하위 폴더에서 만들면 중첩도 가능

<a 태그> vs <Link 태그>: Link가 더 최적화됨
1. 클릭 가로채기
2. 라우터가 경로 변경
3. Prefetch 활용
Link를 사용하면 필요한 컴포넌트만 교체함

route.ts -> 특정 경로에 대한 HTTP Request Handler 정의 가능

 
React는 기본적으로 클라이언트 사이드 렌더링
-> 한계: 실제 전달되는 React 컴포넌트 내용 X, 이후 JS가 동적으로 로드하는 형식
- SEO의 어려움
- 초기 로딩 속도
- JS 비활성화/오류 시 렌더링 불가

Next.js는 서버 사이드 렌더링 제공 -> 완성된 HTML 전달
- 페이지 전환 시 매번 로드
- 로딩 속도로 인한 UX 저하
- SSR을 사용하면 리액트를 쓸 이유가 없지 않나?

-> Next.js는 SSR를 기본으로 하며 CSR의 장점을 취하는 방법을 사용

기본적으로는 모두 Server Component( 이벤트 리스너, 훅 사용 불가) -> 이러한 기능이 필요하면 Client Component로 지정
"use client"

렌더링 된 HTML 로드 후 hydration 수행 (html에 JS 적용)
