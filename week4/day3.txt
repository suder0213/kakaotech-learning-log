React는 라이브러리, Next.js는 프레임워크
둘 다 각각 장단점 존재

> 서버 컴포넌트 / 클라이언트 컴포넌트 좀 더 공부해봐야할 듯

서버 컴포넌트(Next.js 기본값): 서버쪽에서 모두 실행된 상태로 다 만들어진 화면만 브라우저(클라이언트)에게 전달
- useState/ useEffect 불가능
- onClick 사용불가

클라이언트 컴포넌트("use client"): 초기 렌더링 후 브라우저에서 실행되는 컴포넌트
- 클라이언트 함수 자체는 async/await 불가능

사용자와의 인터랙션(클릭, 입력)이 필요하면 클라이언트 컴포넌트로 사용

Server Action("use server"): 서버 전용 함수

SSR의 한계를 최소화하는 전략
- 한계: 초기 로딩은 빠르지만 인터랙션과 실시간 상태 변화 처리가 어려움
- 서버/ 클라이언트 분리로 해결, 정적인 부분은 서버 컴포넌트가 수행해 자바스크립트 번들 줄이기, 동적인 부분은 클라이언트 컴포넌트로 교체.
- 서버 액션은 API 라우터 핸들러 없이도 클라이언트에서 서버 로직을 수행할 수 있게 함.


SQLAlchemy: ORM, 파이썬 코드로 SQL 작성
-> 프로젝트 규모가 커질 수록 sqlite3같은 직접적인 방식은 관리하기 까다로워짐

--------------------------------------------

engine: 실제 데이터베이스 파일 연결 경로 설정 및 관리
SessionLocal: 데이터베이스 조회 및 DML 수행 세션
Base: 데이터베이스 테이블 연결 기본 틀
Model: Base를 상속받은 엔티티

트랜잭션: 쪼갤 수 없는 논리적 작업 단위
