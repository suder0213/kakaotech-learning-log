환경 변수: 프로세스가 동작할 때 참조할 수 있는 변수
- 컨테이너가 실행되는 동안 참조가능

ENV <key>=<value> (쌍따옴표 무시)
환경변수 참조는 ${VAR} 혹은 $VAR 사용 (전자 선호)

- 접두사를 사용하여 환경 변수를 덮어쓰지 않도록 정의

컨테이너의 휘발성: 컨테이너가 삭제되면 데이터도 같이 삭제됨 -> 데이터를 외부에 저장할 필요 있음

데이터 영속화: bind mount, volume

bind mount: 호스트 머신의 FileSystem을 직접 마운트
volume: 도커에서 관리하는 특정 공간에 마운트
- volume은 bind mount에 비해 호스트 머신의 파일시스템에 영향을 덜 받음
- 웬만하면 volume이 더 나은 경우가 많음
+

VOLUME: 마운트 할 컨테이너의 경로를 표기
- 이름을 지정 안하면 해시값으로 만들어져 관리 어려움
(마운트 포인트??)

바인드 마운트
- 저장 위치: 유저가 정한 호스트 컴퓨터의 특정 dir
- 관리 주체: 유저
- 접근성: 탐색기에서 바로 열고 수정 가능
- 주요 용도: 소스 코드 공유, 실시간 개발

볼륨
- 저장 위치: 도커가 정한 호스트 컴퓨터의 특정 dir
- 관리 주체: 도커
- 접근성: 도커를 통해서 접근하는 것이 원칙
- 주요 용도: 데이터베이스 파일, 로그, 설정값 보존


네트워크
- 컨테이너는 기본적으로 격리된 자원이므로 다른 컨테이너와 통신하기 위해선 별도의 수단이 필요함

도커 네트워크: 컨테이너 간 IP 또는 DNS로 통신할 수 있는 격리된 네트워크 제공
 (bridge, host 자주 사용) 도커 엔진은 기본적으로 3가지 드라이브 기반의 네트워크 존재
- docker network: 기본적으로 bridge 네트워크 사용
- 기본적으로 IP 주소를 통한 컨테이너간 통신 지원 ( DNS, 컨테이너 이름 통신 지원)
- 네트워크 생성 후 컨테이너를 만들 때 network를 지정해주면 DNS로 통신 가능


다중 컨테이너: 여러 개의 컨테이너가 하나의 애플리케이션 구성 ( BE, FE, DB 컨테이너를 분리하여 네트워크로 통신, 하나의 서비스처럼 동작 )
- 변경/배포 독립, 유지보수 쉬움, 장애 국소화 <- 중요!
- 스케일링 단위에 따라 부하량이 다름, 따로 확장
- 언어/환경 독립
