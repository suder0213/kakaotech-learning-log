## 1주차: 나나를 깨우다 (6/29~7/3)

**미션**
- 환경 세팅, 자연어 요청이 `tool_call → tool_result`로 흐르는 걸 trace로 따라가기
- 나나에게 일정 **생성 / 조회 / 삭제** 도구를 달고, 모델이 상황에 맞는 도구를 골라 쓰는지 확인

| 날짜 | 구현 | 개념 | 예습 (→ 2주차: Pydantic) |
|------|------|------|--------------------------|
| 6/29 (월) | web 기초 실습 파일 제작 ✅ | label/input, Promise, Node.js | Pydantic이 뭔지 한 줄 개요 |
| 6/30 (화) | 환경 세팅, tool_call → tool_result 출력 확인 | 일반 챗봇 vs Agentic AI 차이 | Pydantic `BaseModel` 기본 문법 |
| 7/1 (수) | 일정 생성 도구 구현, trace 연결 | trace 읽는 법 — 어느 단계에서 tool이 선택되는지 | Pydantic `Field`, 타입 힌트 |
| 7/2 (목) | 조회 / 삭제 도구 구현 | tool description 문구가 선택에 미치는 영향 실험 | Pydantic `kind` 필드 분기 패턴 |
| 7/3 (금) | 1주차 전체 흐름 통합 테스트 & 코드 리뷰 | tool 3개가 어떤 기준으로 선택되는지 정리 | Pydantic 파싱 실패 케이스 처리 |

## 2주차: 자연어를 구조화된 요청으로 (7/6~7/10)

**미션**
- Pydantic으로 일정 / 할 일 / 알림 스키마 설계, `kind` 필드로 요청 분기
- 애매한 요청도 에러 없이 안전하게 분류하는 패턴 만들기

| 날짜 | 구현 | 개념 | 예습 (→ 3주차: SQLite) |
|------|------|------|------------------------|
| 7/6 (월) | 일정 요청 스키마 설계 (`ScheduleRequest`) | Pydantic validation 에러 구조 | SQLite란 — 파일 기반 DB 개념 |
| 7/7 (화) | 할 일 / 알림 스키마 추가 | Union 타입, discriminated union 패턴 | SQL 기본 쿼리 (CREATE, INSERT, SELECT) |
| 7/8 (수) | `kind` 필드 분기 구현 | LLM 출력이 스키마를 못 맞출 때 대응 전략 | 테이블 설계 — 일정/할일/알림 컬럼 구상 |
| 7/9 (목) | 애매한 요청 fallback 분류기 구현 | 안전한 분류 패턴 — 에러 없이 처리하는 법 | `request_id`로 데이터 연결하는 패턴 |
| 7/10 (금) | 2주차 전체 파이프라인 테스트 & 코드 리뷰 | 스키마 설계가 왜 초반에 중요한지 정리 | Python `sqlite3` 모듈 기본 사용법 |

## 3주차: 나나의 기록장을 만들다 (7/13~7/17)

**미션**
- SQLite에 일정 / 할 일 / 알림 테이블 설계, 원본 payload 보존
- `kind`에 따라 알맞은 테이블로 분기 저장, `request_id`로 원본 ↔ 정규화 데이터 연결

| 날짜 | 구현 | 개념 | 예습 (→ 4주차: ChromaDB RAG) |
|------|------|------|-------------------------------|
| 7/13 (월) | SQLite 연결, 테이블 3개 생성 | 정규화 vs 비정규화 — 언제 어떻게 쓰는지 | 임베딩이란? 벡터 유사도 직관적 이해 |
| 7/14 (화) | 원본 payload 보존 컬럼 추가 | JSON 컬럼 저장 패턴 | RAG 전체 흐름 (질문 → 검색 → 컨텍스트 주입) |
| 7/15 (수) | `kind` 분기 저장 구현 (2주차 파이프라인 연결) | 트랜잭션 — 저장 실패 시 롤백 | ChromaDB 기본 구조 (`collection`, `add`, `query`) |
| 7/16 (목) | `request_id`로 원본 ↔ 정규화 추적 구현 | 인덱스 — 검색이 느릴 때 해결법 | ChromaDB vs SQLite — 어떤 질문이 어디로 가야 하는지 |
| 7/17 (금) | 3주차 전체 저장 흐름 테스트 & 코드 리뷰 | 1~3주차 데이터 흐름 전체 정리 | ChromaDB 실제 검색 결과 구조 확인 |

## 4주차: 나나가 기억을 찾아오다 (7/20~7/24)

**미션**
- ChromaDB로 참고자료를 임베딩 저장, 의미 기반 검색 RAG 도구 만들기
- 나나가 ChromaDB(참고자료) vs SQLite(저장 일정)를 스스로 골라 검색하는 듀얼 RAG 구성

| 날짜 | 구현 | 개념 | 예습 (→ 5주차: MCP) |
|------|------|------|----------------------|
| 7/20 (월) | ChromaDB 설치, 참고자료 임베딩 저장 | 임베딩 모델 — 어떤 기준으로 고르는지 | MCP 개념 — 왜 등장했고 뭘 해결하는지 |
| 7/21 (화) | 의미 기반 검색 도구 구현 | 검색 결과 품질 — 엉뚱한 문서가 딸려올 때 | MCP 서버 / 클라이언트 통신 구조 |
| 7/22 (수) | ChromaDB vs SQLite 분기 결정 로직 구현 | 어떤 질문이 어떤 DB로 가야 하는지 프롬프트 설계 | MCP `tools` 스키마 정의 방법 |
| 7/23 (목) | 듀얼 RAG 통합 — 나나가 소스를 스스로 선택 | RAG 한계 — 키워드 검색과 조합하는 이유 | MCP 실제 구현 예시 훑기 |
| 7/24 (금) | 4주차 전체 검색 흐름 테스트 & 코드 리뷰 | 듀얼 RAG에서 선택 기준이 모호할 때 대응 | 대화 히스토리 저장 구조 구상 |
