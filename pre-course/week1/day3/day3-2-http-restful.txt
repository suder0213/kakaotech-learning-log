# 2 HTTP 프로토콜과 핵심 특징

프로토콜: 통신의 과정에 필요한 약속, 형식 등
네트워크 통신에서 데이터를 교환하ㅣ 위한 규칙과 표준 제공

HTTP 프로토콜: 클라이언트-서버 간 데이터가 교환되는 방식에 대한 규약, 거의 몯느 형태의 데이터 전송 가능. 무상태성과 비연결성 !

무상태성: 서버가 클라이언트의 상태를 보존하지 않음
-> 확장성이 용이

비연결성: 클라이언트-서버 간 연결을 유지하지 않음
-> 자원 최적화 및 유연성

HTTPS: HTTP의 보안 버전, 데이터 암호화 ( TLS/SSL 프로토콜 사용 )

# 3. HTTP 메시지와 HTTP 메서드

HTTP 메시지 구조: 시작 라인, 헤더, 공백, 본문으로 구성

CRUD: CREATE READ UPDATE DELETE
	각각 POST GET PUT/PATCH DELETE 메서드로 매치됨

GET: 데이터를 조회( 요청 본문 X )
POST: 서버에 데이터를 전송하여 새로운 데이터를 생성, 서버의 상태를 변경함, 요청 본문에 데이터 포함
PUT: 서버에 데이터를 전송하여 리소스를 완전히 대체, 본문에 데이터 포함
PATCH: PUT과 비슷, 일부만 변경
DELETE: 특정 리소스 삭제

# 4. HTTP 요청 메시지/응답 메시지

HTTP 메시지: 요청 메시지와 응답 메시지로 나뉨

요청메시지

- HOST, ACCEPT, AUTHORIZATION, COOKIE 등 포함 가능

# 5 HTTP 상태 코드
클라이언트의 요청에 대한 서버의 응답을 나타내는 자리 숫자 코드

1XX 정보 응답: 요청을 받았으며 프로세스를 계속함
2XX 성공: 요청을 성공적으로 수신하고 실행함
3XX 리다이렉션: 요청 완료를 위해 추가 작업 조치 필요
4XX 클라이언트 오류: 클라이언트의 요청 오류
5XX 서버 오류: 서버의 응답 오류

# 6 REST API 개요

REST: 자원을 이ㅡㅁ으로 식별하여 자원의 상태 정보를 주고 받음

API: 시스템 간 상호작용을 위한 인터페이스

REST API: HTTP 프로토콜에 기반하여 REST 원칙을 따르는 API

1. 클라이언트- 서버 구조에 기반
2. 무상태
3. 캐시 처리 가능
4. 계층화 시스템
5. 인터페이스 일관성
6. 코드 온 디멘드

#7 REST API의 구성요소

자원, 행위, 표현

자원: URI로 구별됨
URI: 정보의 자원, 자원 식별자 ( URL은 URI다 )

URI: SCHEME, HOST, PORT, PATH, QUERY PARAMETERS, FRAGMENT IDENTIFIER로 구성

행위: HTTP 메서드
일관된 인터페이스
1. 리소스명은 명사
2. 리소스에 대한 행위는 HTTP 메서드
3. 소문자 사용
4. 계층은 슬래시로 구분
5. 마지막엔 슬래시 안 씀
6. 언더바 대신하이픈 사용

표현: HTTP 메시지 페이로드
JSON, XML 등


REST API 기본 설계 원칙
1. 자원 식별: 모든 것은 고유 주소를 가져야 함
2. 표현을 통한 자원의 조작: JSON 등의 표현으로 자원을 조작해야 함
3. 자기 서술적 메시지: 메시지가 자기 자신을 어떻게 처리해야 할지 설명해야 함
4. HATEOAS: 웹 페이지가 다른 페이지나 상태로 넘어갈 수 있도록 링크를 제공해야함

(사실 3, 4는 실무에서 잘 안 지켜지긴 함)
