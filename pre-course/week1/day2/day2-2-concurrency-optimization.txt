asyncio.gather()
인자: 여러 awaitable
반환: 결과 리스트

입력 순서와 출력 순서 동일

작업 중 하나의 예외 발생 시 나머지 작업 처리가 직관적이지 않음


작업의 의존성이 있다면 순차 실행해야 함

비동기 라이프 사이클
코루틴 객체 -> 이벤트 루프 구동 -> 작업 지시 및 제어권 양보

gather -> 반환값은 동시에 받지만 (함수 종료는 기다리지만) 그 사이의 출력문 등은 병렬적으로 수행하는듯

taskgroup -> gather가 동시 실행이라면 태스크 그룹은 해당 작업들의 생명주기를 관리 (예외 발생 시 안전하게 취소)

async for item in aiter:
비동기 이터레이터 순회

async with aiohttp:ClientSession() as s:
비동기 컨텍스트 매니저, 블록 진입 시 연결, 종료시 자동 정리

with 블록 끝나면 모든 태스크 완료 보장, 하나가 실패하면 나머지도 자동 취소

gather -> 각 작업이 독립적일 때 유리
taskgroup -> 작업간 의존성이 높을 때 유리

실제 서비스 환경에서 예외처리가 중요할 때 task group이 자주 사용됨


비동기 파이프 라인
1. async def로 선언
2. await를 사용하여 대기 및 실행
3. asyncio.gather 를 사용해 동시 조율
4. asyncio.run 을 사용해 진입점 명시

실전 비동기
대규모 네트워크 API 요청 시 응답 순서와 무관하게 준비된 데이터부터 처리

http와 비동기 처리를 사용한 예시 코드


import asyncio
import time
import httpx

URLS = [
    "https://httpbin.org/delay/1",
    "https://httpbin.org/delay/2",
    "https://httpbin.org/delay/1",
]

# fetch_url 비동기 함수를 완성하세요
async def fetch_url(url: str) -> dict:
    # 클라이언트 생성 및 GET 요청을 보내세요
    client = httpx.AsyncClient()
    response = await client.get(url)
    
    await client.aclose() # 클라이언트를 닫기
    # 딕셔너리를 반환하세요
    return {"url": url, "status": response.status_code}
    

# fetch_all 비동기 함수를 작성하세요
async def fetch_all(urls: list[str]) -> list[dict]:
    tasks = [fetch_url(url) for url in urls]
    results = await asyncio.gather(*tasks)
    return list(results)

async def main():
    start = time.time()
    # fetch_all을 호출하고 결과를 출력하세요
    results = await fetch_all(URLS)

    for r in results:
        print(f"{r['url']} -> {r['status']}")

    elapsed = time.time() - start
    print(f"\n전체 소요 시간: {elapsed:.1f}초 (순차 호출 시 약 4초)")

asyncio.run(main())
