Agent의 동작은 평가 전까진 그럴듯 해보임(할루시네이션)
-> 대충했다간 엄청난 배상 책임으로 돌아올 수도

현재 LLM은 '유창함'은 충족 -> 이제 '정확함'을 평가할 차례

Text 생성 모델 평가 방법
- 형식만 발전시키면 비슷하게 영상 / 데이터 / 음성 평가 가능
- Human Evaluation (Gold Standard): 사람이 직접 평가 --> 생각보다 매우 중요!
	- MOS(Mean Opinion Score): 사람의 의견 점수 평균
- Perplexity: text 생성 모델이 동작하는 방법을 기반으로 얼마나 정확한 문장을 만들었는지
	- base/pre-trained 모델을 평가하는 방법 중 하나
	- P(word | context)
{
양자화: 모델의 가중치나 연산 숫자를 더 낮은 비트로 바꿔서 수행
- INT 4, 8, 16
	- 8, 16은 차이 별로 없는데 4는 SLM이면 차이가 큼
}

위는 '유창함'을 평가하는 것, '정확함'은 평가 안됨

BERT Score: embeding을 사용한 평가
- 실제 정답과 생성된 정답이 얼마나 유사한가?
- QA를 직접 만들어야 함... -> 이게 핵심
	- 모델의 '정확함'을 평가하기 위해선 정답 데이터셋을 만들어야 함. 결국은 **데이터 싸움!**
- 유창함 / 정확함을 반반 평가하는 느낌

생성 모델
- '확률의 렌즈'
- 실제 데이터가 특정 벡터 공간에 표시됨 -> 생성 모델: 벡터 공간에 근사하여 표현


LLM-as-a-Judge: Prompt를 사용하여 평가하는 방법
- 점수를 매기게
- 정제 프롬프트 ex) 장황함은 무시하며, 불필요한 길이를 보상하지 마라

어떤 질문과 답변을 만들어 평가할 지가 중요
- 해당 모델이 동작할 도메인에서 어떤 질문과 답변이 나올 것인지 예측해서 데이터셋을 만들기
- 질의응답세트 <- 이거 만드는게 중요	

모델 평가 < 오질나게 중요
