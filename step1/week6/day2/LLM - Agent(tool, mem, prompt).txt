Multi-Agent workflows
- Sub-Agent나 sworm은 LLM의 판단을 믿는 반면, multi-agent는 사람이 특정 조건에 따라 조종하는 느낌
- 'state'라는 것을 관리
- 지금은 tool_call을 통해 자동화되는 것이, state에 따라 if문으로 분기됨
	- 초기 라마 인덱스, 랭그래프

멀티/서브 에이전트에서 가장 중요하게 다뤄지는 것
- context를 전달하는 방법
	- 문서화? 요약해서 전달?

Sub-Agent: Agent를 tool처럼 불러서? function invoke
- Main Agent의 Context에 과정이 쌓이지 않음 -> context 절약, 성능 향상 기대
- agent마다 tool을 할당하여 사용
- middleware: HITL(human in the loop)로 어느정도 제어도 가능
- task를 잘게 쪼개서 전문가들을 만들고, 그 전문가들을 어떻게 부를까... 하는거
